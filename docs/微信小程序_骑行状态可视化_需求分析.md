# 微信小程序：骑行状态可视化需求分析（V1）

## 1. 文档目的
将已确认的产品需求收敛为可执行的 V1 基线，作为后续技术方案、排期与实现拆分依据。

## 2. 项目定位
本项目是一个微信小程序，通过手机传感器实时驱动 Q 版小猫骑电动车动画，将骑行状态具象化呈现。

定位关键词：
- 实时
- 可视化
- 角色驱动
- 轻提醒
- 城市通勤

## 3. 已确认约束与范围

### 3.1 平台与设备
- 平台：微信小程序
- 手机形态：固定在车把支架，竖屏使用
- 传感器来源：仅手机自身传感器（不接蓝牙外设）

### 3.2 使用场景
- 场景优先级：城市通勤
- 产品目标：骑行中快速瞥一眼即可理解状态

### 3.3 表达方式
- 主表达：角色动画（Q 版小猫骑电动车）
- 辅助表达：极少量状态文案 + 少量关键数据
- 不采用生硬文字主导的信息传达

## 4. 状态模型（最终确认）

### 4.1 主状态（一级）
- 停
- 行

### 4.2 子状态（二级）
- 停：等待启动（红绿灯/临时停靠）
- 行：提速、平稳、转弯、刹车/减速、颠簸

### 4.3 判定原则
- 先判主状态（停/行）
- 再判行中子状态
- 主状态优先稳定，子状态追求可感知

### 4.4 行中子状态优先级
1. 刹车/急减速
2. 明显转弯
3. 提速
4. 连续颠簸
5. 平稳

## 5. 角色动作映射（V1）

### 5.1 停：等待启动
- 小猫一只脚踩地撑车
- 车辆原地待命
- 保留轻微呼吸/尾巴摆动微动画

### 5.2 行：提速
- 小猫轻微前倾
- 车辆有短时前冲感
- 增加简短风线特效

### 5.3 行：平稳
- 车轮稳定转动
- 小猫表情放松
- 保持低幅度连续微动

### 5.4 行：转弯
- 根据幅度连续偏转车头
- 小猫身体与头部轻度侧倾跟随

### 5.5 行：刹车/减速
- 车辆前压或轻微后翘（保留“翘屁股”演出点）
- 小猫表情进入紧张态
- 可叠加轻量刹车线/摩擦效果

### 5.6 行：颠簸
- 车体与角色高频小幅抖动
- 可叠加震动线特效

## 6. 页面结构（竖屏车把场景）

采用：舞台 + 底部状态条（竖屏优化）

### 6.1 准备页
- 权限检查（定位/传感器）
- 固定手机在车把提示
- 开始感应按钮

### 6.2 主页面（核心）
- 上部：角色主舞台（大面积）
- 中部：状态短文案条（高对比、短文本）
- 下部：极简数据条（速度、时长、坡度趋势或事件计数）
- 底部：单一主按钮（结束骑行）

### 6.3 结束页
- 本次骑行时长
- 大致距离
- 速度摘要（最高或平均）
- 关键事件计数（如刹车、颠簸、转弯）
- 一句趣味总结

## 7. MVP 功能清单（必须做）
1. 传感器采集与基础滤波
2. 停/行主状态稳定判定（防抖、滞回）
3. 行中 5 子状态判定
4. 动画驱动（主状态基底 + 子状态叠加）
5. 竖屏主界面渲染与状态展示
6. 单次骑行统计与结束页展示

## 8. V1 不做项
- 蓝牙设备接入
- 地图轨迹回放
- 历史骑行系统
- 社交/排行/成就
- 专业安全评分与事故级判断
- 多载具深度支持

## 9. 技术与体验风险
1. 小程序传感器连续性受机型与系统影响
2. 低速定位速度抖动会影响停/行判断
3. 安装角度差异会影响姿态阈值稳定性
4. 阈值敏感会导致状态乱跳和动画抽搐
5. 动画演出过强会削弱“可信反馈”感

## 10. 验收标准（V1）
1. 停/行切换稳定，不在阈值附近来回抖动
2. 行中 5 子状态可感知、可区分
3. 用户无需阅读长文案即可理解当前状态
4. 竖屏远看可读，角色演出明显优先于数据
5. 连续使用体验流畅，不出现明显卡顿

## 11. 版本路线建议
- V1：停/行 + 行中 5 子状态 + 角色主舞台 + 基础统计
- V1.1：强化上下坡趋势与异常晃动识别，补充参数调优能力
- V1.2：扩展多载具主题、角色换装与演出丰富度
