# 首轮外场采集与电脑回放验证

更新：2026-09-17。目标是一次采集带回可重复使用的数据，不要求每次修改都外出。

## 室内先检查

1. 开发者工具导入根目录并配置有效 AppID、定位接口与隐私指引。
2. 在 iPhone 17 打开，验证拒绝定位时提示、授权后重试。
3. 固定手机，点击开始；2 秒倒计时内尽量不要大幅动作。
4. 校准中切后台再返回，应重新校准，不使用部分旧数据。
5. 调整支架后点击重新校准。
6. 静止时轻微晃动手机，不应仅凭晃动判为骑行。
7. 从舞台导出记录并在准备页再次导出同一会话。电脑工作台应能导入。

## 一次外场采集

在安全环境下正常骑行，不为测试特意做危险动作。不要骑行中操作调试按钮。

1. 停车等待约 15 秒。
2. 正常起步，直行约 30 秒。
3. 正常减速停车，等待约 15 秒。
4. 低速挪车后停车，观察是否来回切换。
5. 停稳后切微信聊天，再回到小程序。
6. 停稳后调整支架并重新校准，再骑行一小段。
7. 停稳后导出本次记录，存到电脑。

记录明显不符的时间段和实际动作，便于在电脑跳转。无需为首轮采集转弯、颠簸和刹车专属状态。

## 电脑复测

1. npm run replay，浏览器打开本地工作台。
2. 导入真实 JSONL，先用记录参数回放完整一遍。
3. 对照原始判定与记录参数重算（相同引擎版本应一致）。
4. 在问题时间段暂停，调整起步速度 / 确认时间或停车阈值 / 确认时间。
5. 应用后查看整段差异与两条状态时间线，避免只修好一个片段却破坏别处。
6. 导出参数 JSON；采用参数时更新代码 DEFAULTS 与引擎 VERSION，再用所有已有记录复测。
