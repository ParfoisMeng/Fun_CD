# 微信小程序：骑行状态可视化实现计划（V1）

## 1. 计划目标
基于《微信小程序_骑行状态可视化_需求分析.md》落地 V1，可在微信小程序中完成：
- 停/行主状态稳定识别
- 行中子状态（提速、平稳、转弯、刹车/减速、颠簸）识别
- Q 版小猫骑电动车动画主导展示
- 单次骑行结果页输出

## 2. 技术方案总览

### 2.1 架构分层
1. Sensor Layer（采集层）
- 采集定位速度、加速度、陀螺仪、姿态角（按小程序可用能力）
- 时间戳对齐与基础缓冲

2. Signal Layer（信号处理层）
- 去噪/平滑（滑动窗口 + 指数平滑）
- 特征提取（短窗均值、峰值、方差、趋势）

3. State Layer（状态判定层）
- 主状态 FSM：停/行
- 子状态判定：提速、平稳、转弯、刹车/减速、颠簸
- 防抖、滞回、最短保持时间

4. Animation Layer（演出层）
- 主状态基底动画（停、行）
- 子状态叠加动画（事件优先级覆盖）
- 特效调度（风线、震动线、刹车线）

5. UI Layer（界面层）
- 准备页、主页面、结束页
- 状态文案短句映射
- 数据条渲染

6. Session Layer（会话层）
- 单次骑行统计（时长、距离、速度摘要、事件计数）
- 结束页数据输出

### 2.2 状态引擎核心原则
- 先判主状态，再判子状态
- 主状态变化比子状态更保守
- 高优先级子状态可覆盖低优先级演出
- 演出层与判定层解耦，支持后续阈值调优

## 5. 判定逻辑（V1 规则化）

### 5.1 主状态：停/行
- STOP -> MOVE 条件：速度/运动特征超过启动阈值并持续 T1
- MOVE -> STOP 条件：速度与运动特征低于停止阈值并持续 T2
- 其中 T2 > T1（退出更保守）
- 引入滞回阈值区间避免抖动

### 5.2 子状态（仅在 MOVE 中判定）
- BRAKE：纵向减速度显著 + 速度趋势下降
- TURN：偏航角速度显著（可区分左右，供车头偏转）
- ACCEL：纵向加速度为正 + 速度趋势上升
- BUMP：垂向振动能量高于阈值
- CRUISE：均不命中或低强度稳定运动

### 5.3 子状态优先级
BRAKE > TURN > ACCEL > BUMP > CRUISE

## 6. 动画实现策略（混合方案）

### 6.1 主状态动画
- STOP：小猫单脚撑地待机
- MOVE：基础骑行动画循环

### 6.2 子状态叠加
- ACCEL：短时前倾 + 风线
- TURN：车头旋转 + 身体侧倾（连续参数驱动）
- BRAKE：前压/后翘 + 紧张表情
- BUMP：高频小幅抖动 + 震动线
- CRUISE：平稳微动

### 6.3 动画防抖
- 每个子状态最短保持时长
- 高优状态触发冷却
- 强制过渡帧避免硬切

## 7. 页面与交互落地

### 7.1 准备页
- 显示权限状态（定位、运动）
- “固定手机到车把”提示图
- 主按钮：开始感应

### 7.2 主页面（竖屏）
- 上部：角色主舞台（约 65% 高度）
- 中部：状态短语条（4~6 字优先）
- 下部：数据条（速度、时长、趋势）
- 底部：结束骑行

### 7.3 结束页
- 时长、距离、速度摘要
- 事件计数
- 趣味总结文案

## 9. 测试清单（最小可执行）

### 9.1 功能测试
1. 权限拒绝/允许路径完整
2. 停 -> 行 -> 停主链路稳定
3. 子状态识别可触发且可区分
4. 结束页统计数据完整显示

### 9.2 场景测试
1. 红绿灯起停
2. 直行巡航
3. 正常转弯与急转
4. 减速带/井盖颠簸
5. 急减速（安全可控环境）

### 9.3 稳定性测试
1. 连续 20 分钟骑行不卡死
2. 状态切换不过度抖动
3. 动画帧率与交互响应可接受

## 10. 参数调优策略
- 所有阈值集中配置，禁止散落硬编码
- 支持导出状态日志（时间戳 + 传感器特征 + 判定状态）
- 每轮外场后按日志回放调参
- 先调主状态，再调子状态
